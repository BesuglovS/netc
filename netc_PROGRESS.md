## 0.2 Сессия 13.10.2026 (продолжение) — экран блокировки через сторожа; активация без перезагрузки

Задача: починить «лок-скрин: нет прав (нужен админ)» при применении персонализации из клиента.

**Причина:** экран блокировки — машинный ключ `HKLM\...\PersonalizationCSP`; агент в сессии ученика
(обычный пользователь) писать в HKLM не может. Удалённая правка ACL через RemoteRegistry
**не поддерживается** (проверено на 10.12.6.15 — `SetAccessControl` на удалённом ключе падает).
Решение (выбран вариант A): машинную настройку выполняет **служба-сторож (SYSTEM)**.

**Сделано:**
- `netc_shared\MachinePersonalization.cs` — контракт обмена: папка `C:\ProgramData\netc\personalize`,
  запросы `req-*.json` / ответы `res-*.json` (действия `set` / `reset` / `restart-agent`).
- `NetcServer.Watchdog\MachinePersonalizationWorker.cs` — новый hosted-service: создаёт папку обмена
  (право Modify для «Пользователи»), от SYSTEM пишет HKLM CSP; по `restart-agent` убивает агента
  (WatchdogWorker поднимает свежий). В csproj сторожа добавлена ссылка на `NetcShared`.
- `NetcServer.Agent\Personalization.cs` — если своих прав нет, агент шлёт запрос сторожу
  (`RequestViaWatchdog`), ждёт ответ до ~8 с; иначе работает как раньше (напрямую).

**Проверено на R114-03 (10.12.6.15):** `лок-скрин=ок`; ключ `PersonalizationCSP` на ПК заполняется
(`LockScreenImageStatus=1`, `LockScreenImagePath=%LOCALAPPDATA%\netc\lockscreen.jpg`); сброс —
`status=0`, path пусто. Второй ПК (10.12.6.19) — тоже `лок-скрин=ок`.

**Развёртывание (13.10, без перезагрузки ПК):** `…\Temp\opencode\netc_deploy\LockScreenRollout3.ps1`
(агентские DLL + `NetcServer.Watchdog.exe`, `sc stop/start netc_watchdog` с таймаутами) — **19/19**;
`ActivateAgents.ps1` (действие `restart-agent`) — **19/19**, агенты перезапущены, порты 7801 поднялись.
`C:\agent` синхронизирован. Тестовое средство: `netc_locktest` (`set <img>` / `reset`).

**Грабли:** `sc.exe` на этих ПК медленный и иногда подвисает на отдельном ПК — в скриптах ставить
таймаут (`Start-Process` + `WaitForExit`) и **не делать цикла опроса** `sc query` (много вызовов = минуты).
Имя функции `Sc` конфликтует с алиасом `sc` = `Set-Content` (алиасы приоритетнее функций).

**Обои-цитаты (13.10):** 19 картинок из `C:\admin\files\quotes-wallpapers` разложены по ПК «по порядку»
(R114-01→01…R114-19→19, режим «Заполнить») — **19/19 OK** через канал персонализации (инструмент
`netc_wall` в temp). Клиент не использовался.

- **Wake-on-LAN — готово:** агент отдаёт MAC в `PcInfo` (`PcInfoProvider.GetMac`), клиент —

### Обновление уже установленного агента «на живую» (без перезагрузки процесса)

Агент запущен из `C:\Program Files\netc`, его DLL заняты процессом. Схема, которая работает:

1. Скопировать новый файл **прямо поверх** (`Copy-Item -Force`). Срабатывает, если текущий файл
   на диске **не загружен** процессом (типичный случай после предыдущего обновления — тогда
   загружен старый файл, переименованный в `*.old`).
2. Если прямая перезапись не удалась (файл занят) — переименовать его в **уникальный** `*.old`
   (с таймштампом!) и скопировать новый. Фиксированный `NetcServer.Agent.dll.old` использовать
   **нельзя**: он остаётся занятым старым процессом, и повторное переименование в него падает.
3. Служба-сторож (`netc_watchdog`) обновляется так: `sc stop` → заменить `NetcServer.Watchdog.exe`
   (тем же способом) → `sc start`.
4. Новая сборка активируется **после перезапуска агента** (перезагрузка ПК либо убийство агента —
   сторож поднимет новый).

## 6. Ключевые находки/ограничения

1. **Запуск служб на ученических ПК (перепроверено 10.10.2026):** службы запускать **можно**.
   `RemoteRegistry` стартует; и наш `NetcServer.Service.exe` (текущая self-contained сборка)
   стартует как служба и **слушает порт** (проверено на R114-01/R114-03: `sc create/start` →
   `STATE=RUNNING`, а изнутри ПК порт `7801 OPEN`).
   Прежняя запись про «службы запрещены, ошибка 87» оказалась неверной/частной: события 7000/87
   (09.10.2026) относились к службе с `ImagePath = C:\netc\NetcServer.Service.exe`, а сейчас
   `C:\netc` содержит **агента**, а не службу; та же ошибка 87 тогда же была и у чужих служб
   `CwcAgent/CwcProbe` — это проблемы регистрации/пути конкретных служб, а не запрет на этих ПК.
   Причина, по которой служба не может **заменить** автономного агента, иная — **изоляция сессии 0**
   (см. ниже): служба не видит экран/не вводит мышь-клавиатуру/не рисует окна в сессии ученика.
2. **AppLocker, WDAC, ASR не настроены**, сторонних AV нет (только Defender, обнаружений не было).
   Образ «разработческий»: есть .NET 8 Desktop Runtime, Windows SDK, PyCharm, Blender и т.п.
   (Но наш агент всё равно публикуем self-contained — на случай других ПК.)
3. **Питание:** эффективные значения задаются **групповой политикой** питания
   (`HKLM\SOFTWARE\Policies\Microsoft\Power\PowerSettings\<GUID>\ACSettingIndex=0`).
   Эффективно: дисплей и сон = **«Никогда»** (проверено `powercfg /query`).
   При этом в схеме реестра (`...\Power\User\PowerSchemes\...\ACSettingIndex`) значение
   остаётся `1800` — это НЕэффективное значение, читать его для проверки **нельзя**.
   Правильно проверять через `powercfg /query SCHEME_CURRENT SUB_VIDEO VIDEOIDLE`.
   `powercfg /change` на этих ПК возвращает «Не удалось изменить параметры групповой политики…»
   — это нормально, т.к. политика перекрывает схему.
4. Технические грабли: `sc.exe` на этих ПК медленный (~21 с на вызов); `net use /delete`
   может подвиснуть (использовать API/оставлять сессии); SMB-сессии под `student` ломают
   административные операции (снимать их, иначе «доступ запрещён»).
5. **Wake-on-LAN:** на **Acer TravelMate P215-53** WoL из выключенного состояния (S5) только
   **«Wake on LAN from Dock in S5»** — то есть **нужна док-станция с Ethernet**; без дока
   дистанционное включение невозможно. Другие опции BIOS там: `USB wake from S4`, `TBT Wake from S4`.
   На **ICL RAYbook Bi1504** есть проводной RJ-45 — шанс на WoL из S5 выше, **не проверено**.
   `shutdown /s` переводит ПК в S5 (гибернация отключена) — важно для тестов WoL.
6. **Инцидент (R114-15):** в автозагрузке ученика лежал скрипт `main script.py` с
   `os.system("shutdown/h")` — через 2 с после входа ПК уходил в **гибернацию** (выглядело как
   «выключается»). Аппаратной поломки не было (нет Kernel-Power 41). Скрипт удалён; был только там.
7. **R114-01:** включался сам, когда в его BIOS был включён `Wake on LAN` (NIC «вооружён» и
   просыпается от трафика подсети, в т.ч. от наших проверок/ARP). **10.10.2026 WoL в BIOS R114-01
   выключен пользователем** — сам больше не должен просыпаться. Для этих Acer WoL без дока всё равно
   не работает, так что выключение ничего не ломает.

3. **WoL на ICL RAYbook Bi1504** — включить в BIOS `Wake on LAN` + `ErP Disabled`, в Windows NIC
   «Wake on Magic Packet», проверить кнопкой «Включить». На Acer без дока — невозможно.
4. **Паритет режима службы** (`NetcServer.Service`): сейчас бросает `NotSupportedException` для
   Этапов 3–4 (используется только автономный агент).
5. Возможные расширения: группы/расписание, инвентаризация ПО, обновление агентов из клиента,
   блокировка USB/печати, аудио; включение без дока — через BIOS `RTC Wake` / `Restore on AC Power Loss`.
