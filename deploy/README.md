# Добавление нового ученического ПК в netc

Пошаговый механизм: как добавить новый компьютер в класс, развернуть на нём систему и проверить.
Относится к `netc` (агент на ученических ПК + клиент учителя).

Скрипты лежат в этой папке (`C:\admin\files\deploy\`).

---

## 0. Предпосылки

- На новом ПК есть **локальный администратор** (используется для установки/обновления; локальная, не доменная).
  Учётки и общий ключ задаются в `deploy\secrets.psd1` (шаблон — `secrets.example.psd1`); секреты в
  репозиторий не коммитятся.
- Новый ПК в сети класса (`10.12.6.x`, `10.90.x`, `10.99.x`), Wi-Fi или Ethernet.
- С ПК учителя доступны нужные подсети (для 10.90.x/10.99.x маршрут через `10.12.1.1`).

### Настройка доступа к ПК (один раз)

Скопируйте `secrets.example.psd1` в `deploy\secrets.psd1` и заполните `User`/`Password`/`SharedKey`.
Либо передавайте их параметрами (`-User`, `-Password`, `-SharedKey`) или переменными окружения
(`NETC_DEPLOY_USER`, `NETC_DEPLOY_PASSWORD`, `NETC_SHARED_KEY`).

## 1. Добавить адрес в списки (на ПК учителя)

| Файл | Что добавить |
|---|---|
| `C:\admin\files\ips.txt` | строку `адрес\|R114-NN\|модель` нового ПК (обратно совместимо: только адрес тоже читается) |
| `C:\admin\files\dist\client\netc_pcs.txt` | то же (список клиента; читается при запуске) |
| `C:\admin\files\netc_client\MainForm.cs` → `DefaultPcs` | адрес + имя + модель (резервный список для чистой установки клиента) |

Нумерация — по порядку строк в `ips.txt` (R114-01…). Если имя ПК не `R114-NN`, ориентируйтесь на
реальный IPv4 и `hostname` (их печатает скрипт из шага 2).

Пересобирать клиент для действующей установки **не обязательно** — достаточно строки в `netc_pcs.txt`
рядом с `NetcClient.exe`. Пересборка (`build.ps1`) нужна лишь чтобы обновить встроенный список по
умолчанию в самом exe.

---

## 2. На новом ПК — открыть доступ (один раз, локально, от администратора)

Скопировать на ПК два файла и запустить `.cmd` (двойной клик → UAC → «Да»):

```
enable-remote-access.cmd
enable-remote-access.ps1     (должны лежать рядом)
```

Что делает:
- профиль сети → **Private**; включает общий доступ/обнаружение (best-effort);
- явные правила брандмауэра: **TCP 445, TCP 139, UDP 137/138, ICMPv4 (ping)**;
- включает службу **Server** (LanmanServer);
- `LocalAccountTokenFilterPolicy = 1` — админ-доступ по сети для локального админа;
- `ForceGuest = 0` — классическая модель общего доступа;
- печатает **имя ПК и IPv4** (запишите/сверьте с шагом 1).

> Именно этого не хватает свежей Windows: по умолчанию закрыты и ping, и SMB, а локальному админу
> запрещён сетевой админ-доступ (ошибка `System error 5` при доступе к `C$`).

Если что-то не так:
- `fix-remote-admin.cmd` — только политики доступа (`ForceGuest`, `LocalAccountTokenFilterPolicy`);
- `enable-remote-access.ps1` печатает список администраторов ПК — убедитесь, что `MNU` среди них.

## 3. Развернуть систему (с ПК учителя)

```
powershell -ExecutionPolicy Bypass -File C:\admin\files\deploy\DeployPc.ps1 -Targets "10.90.5.153"
```

Несколько ПК — через запятую: `-Targets "10.x.x.x,10.y.y.y"`.

Что делает `DeployPc.ps1`:
1. проверяет доступность порта 445 и открывает SMB-сессию под `MNU`;
2. копирует свежую сборку (`dist\agent`, self-contained) в `C:\netc_setup` на ПК;
3. создаёт **временную службу** `netc_setup_run`, которая запускает официальный
   `install-agent.ps1` **отсоединённым процессом** и пишет `install.done`/`install.log`
   (с повторами — на части ПК первый запуск службы «не заходит»);
4. дожидается завершения, удаляет службу и папку `C:\netc_setup`;
5. шлёт `restart-agent` — сторож поднимает агента **в сессии ученика**;
6. печатает итог: `done`, хэш `agent.dll`, порт 7801, состояние `netc_watchdog`, результат restart.

Ожидаемая строка:
```
[10.90.5.153    ] done=True dll=97B6700E/97B6700E port7801=open watchdog=RUNNING restart=ok
```

Что ставится: файлы в `C:\Program Files\netc`, `netc.json` (общий ключ, порты 7801/7802 —
порт 7803 не используется и не открывается), правила брандмауэра netc, автозапуск в сессии
(`HKLM\...\Run\netc_agent`), служба-сторож `netc_watchdog` (SYSTEM), отключение сна/гибернации.

## 4. Проверить (с ПК учителя)

```
powershell -ExecutionPolicy Bypass -File C:\admin\files\deploy\VerifyTestBuild.ps1 -Targets "все ip через запятую"
```
Сверяет по каждому ПК: хэши `NetcServer.Agent.dll`/`NetcServer.Core.dll` = `dist\agent`, порт 7801,
состояние `netc_watchdog`. Работает **параллельно** (`-Throttle`, по умолчанию 24) — проход по классу
занимает ~20–25 с (последовательно было ~8 мин). Итог `ok=N/M`; выключенные ПК — `OFFLINE` (норма).

Дополнительно — в клиенте: `dist\client\NetcClient.exe` → «Обновить сведения» → появляются имя/пользователь/модель.

---

## 5. (Опционально) Добавить в сбор работ

`ControlWorksCollector` (сбор папок с рабочих столов за дату) держит свой список ПК в
`%AppData%\ControlWorksCollector\config.json` → `PcRecords` (`Label/Hostname/Mac/Ip`). Для нового ПК
добавьте запись с его IPv4 и (по возможности) `Hostname`. Собирает работы по правилу: папки,
**созданные в выбранную дату**, из `\Users\*\Desktop` и `Public\Desktop`, через `\\ПК\C$` под `MNU`.

## Диагностика (грабли)

| Симптом | Причина | Решение |
|---|---|---|
| ПК не пингуется, порт 445 закрыт | свежая Windows: брандмауэр | шаг 2 — `enable-remote-access.cmd` локально |
| `System error 5` при доступе к `C$` (логин верный) | UAC-фильтрация локального админа / гостевая модель | шаг 2 (или `fix-remote-admin.cmd`) — `LocalAccountTokenFilterPolicy=1`, `ForceGuest=0` |
| `System error 1326/риск` | неверный пароль / учётка не админ | проверить `MNU` в администраторах (`enable-remote-access` печатает) |
| `sc start` временной службы → **1053** | `cmd.exe` не умеет быть службой | так и задумано: установщик запускается отсоединённым процессом; `DeployPc` делает повторы |
| первый запуск установки «не зашёл» на конкретном ПК | гонка при старте службы | `DeployPc` повторяет до 4 раз (наблюдалось на R114-21/22/23) |
| `schtasks /S` → «request is not supported», `netsh -r` → «RPC server is unavailable» | закрыты RPC-порты (135 + динамические) | поэтому установка идёт по SMB (445) + `sc`, без планировщика и удалённого netsh |
| нужен удалённый реестр (`reg \\ПК`) | служба RemoteRegistry выключена | `sc \\ПК config RemoteRegistry start= demand` + `sc \\ПК start RemoteRegistry` |
| ошибка подключения **51** | изоляция клиентов Wi-Fi | настроить сеть/AR — на уровне сети, не netc |
| агент не отвечает после установки | нет активной сессии ученика | войти под `student` (или настроить авто-вход); сторож поднимет агента в сессии |

## Альтернатива: локальная установка

Если удалённый доступ не нужен/невозможен — на новом ПК скопировать папку
`C:\admin\files\dist\agent_setup` (свежая сборка + `install.cmd`) и запустить
**`install.cmd` от администратора**. Ставит то же самое (файлы, `netc.json`, правила брандмауэра,
автозапуск, службу), агент поднимется при входе ученика.

## Обновление уже установленных ПК (не добавление)

Лёгкая раскатка прикладных файлов + перезапуск — `deploy\UpdateAgents.ps1`:
```
powershell -ExecutionPolicy Bypass -File C:\admin\files\deploy\UpdateAgents.ps1 -Targets "10.12.6.16,10.12.6.17"
```
Копирует агентские файлы и файлы сторожа (изменившиеся определяются по хэшу), делает
`sc stop/start netc_watchdog` **только если менялся код сторожа**, и `restart-agent`. Проверка — `VerifyTestBuild.ps1`.

Работает **параллельно по ПК** (`-Throttle`, по умолчанию 6): медленный удалённый `sc.exe` (~21 с
на ПК) перекрывается по нескольким машинам. Ориентиры: проход по 24 ПК «всё актуально» — ~15 с;
полное обновление 24 ПК — ~1–2 мин (вместо ~10 мин последовательно). Журнал — с метками времени
и фазовой разбивкой (`stop/copy/start/restart`).

| Файл | Назначение |
|---|---|
| `deploy\enable-remote-access.cmd` / `.ps1` | ЛОКАЛЬНО на новом ПК: открыть SMB/ping + админ-доступ, напечатать имя+IP |
| `deploy\fix-remote-admin.cmd` | ЛОКАЛЬНО: только политики доступа (`ForceGuest`, `LocalAccountTokenFilterPolicy`) |
| `deploy\_common.ps1` | общий разбор учётки/ключа для скриптов развёртывания |
| `deploy\secrets.psd1` | ЛОКАЛЬНО (не коммитится): учётка и общий ключ; шаблон — `secrets.example.psd1` |
| `deploy\DeployPc.ps1` | с ПК учителя: разложить и установить агент + сторож |
| `deploy\UpdateAgents.ps1` | с ПК учителя: лёгкое обновление уже установленных ПК |
| `deploy\VerifyTestBuild.ps1` | с ПК учителя: сверить хэш/порт/службу по списку ПК |

| `ips.txt` | общий список ПК класса (`адрес\|имя\|модель`) |
| `netc_tests\` | юнит-тесты (`dotnet test netc_tests`) |
