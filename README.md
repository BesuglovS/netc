# netc — комплекс управления компьютерами учебного класса

Аналог Net Control 2 Classroom. Состоит из двух частей:

- **`netc_server`** — устанавливается на ученические ПК (агент-служба + трей-агент);
- **`netc_client`** — приложение на ПК учителя (пульт управления).

## Структура

```
netc.slnx
├── netc_shared/                      общий код: протокол, AES-GCM, модели, настройки
├── netc_server/
│   ├── NetcServer.Core/              ядро: TCP-сервер, обнаружение, backend-интерфейс
│   ├── NetcServer.Agent/            автономный агент в сессии ученика (трей, сеть, экран, ввод)
│   ├── NetcServer.Service/          вариант «служба сети + агент» (опционально)
│   ├── NetcServer.Watchdog/         служба-сторож (SYSTEM): держит агент запущенным
│   └── install/
│       ├── install-agent.ps1        установка автономного агента + сторожа
│       ├── install.cmd              запуск двойным кликом
│       └── set-power.ps1/.cmd / uninstall.ps1
├── netc_client/                      приложение учителя (WinForms)
├── netc_android/                     приложение учителя на планшете Android (.NET for Android)
├── Directory.Build.props              единая версия комплекса (NetcVersion) для всех проектов
├── build.ps1                         публикация (агент/сторож self-contained папкой; клиент single-file)
└── build-android.ps1                 сборка APK учителя для планшета
```

## Устойчивость агента

На ученических ПК ставится служба **`netc_watchdog`** (работает от SYSTEM). Она следит за
процессом агента в сессии ученика и **перезапускает его, если ученик закрыл агента** (Диспетчер
задач / «Выход» в трее). Службу ученик остановить не может (нужны права администратора).
Проверено: после завершения агента сторож поднимает его в сессии `student` в течение ~8–12 с.

## Требования

- **Сборка:** .NET SDK 10 на машине учителя/разработчика.
- **Ученические ПК:** ничего ставить не нужно — сборка self-contained (рантайм .NET лежит рядом
  с приложением). Сторож публикуется папкой (а не single-file), поэтому обновления весят сотни КБ.
- Windows 10/11.

## Сборка

```powershell
powershell -ExecutionPolicy Bypass -File .\build.ps1
```

Результат:
- `dist\agent` — автономный агент + сторож (`NetcServer.Agent.exe`, `NetcServer.Watchdog.exe`;
  self-contained, папкой — при обновлении копируются только изменённые файлы);
- `dist\service` — служба `NetcServer.Service.exe` (опционально);
- `dist\client` — `NetcClient.exe` (self-contained, single-file).

Сборка приложения учителя для планшета Android:

```powershell
powershell -ExecutionPolicy Bypass -File .\build-android.ps1
```

Результат: `dist\android\NetcAndroid.apk` (подробности — `netc_android\README.md`).

## Установка на ученический ПК

Скопировать на ученический ПК папку **`dist\agent_setup`** (сборка агента + `install.cmd`) и запустить
**от администратора** `install.cmd` (либо тот же установщик `install-agent.ps1` из
`netc_server\install`):

```powershell
powershell -ExecutionPolicy Bypass -File .\install-agent.ps1 -SharedKey "ваш-секрет"
```

Скрипт: останавливает прежние сторож и агент, копирует файлы в `C:\Program Files\netc`
(зеркалированием), пишет `netc.json`, открывает порты
(TCP 7801, 7803; UDP 7802), задаёт питание, добавляет автономный агент в автозапуск
(`HKLM\...\Run\netc_agent`) и регистрирует службу-сторож **`netc_watchdog`**, которая держит
агента запущенным в сессии ученика.

Удаление:

```powershell
powershell -ExecutionPolicy Bypass -File .\uninstall.ps1
```

### Добавление нового ПК в класс (актуальный механизм)

Актуально ставится **автономный агент + сторож** (`netc_watchdog`), а не служба `netc_server`.
Полная пошаговая инструкция — **[`deploy/README.md`](deploy/README.md)**. Кратко:

1. Добавить IPv4 в `ips.txt`, `dist\client\netc_pcs.txt` и `netc_client\MainForm.cs` (`DefaultAddresses`).
2. **Локально на новом ПК** один раз запустить `deploy\enable-remote-access.cmd` (от администратора):
   откроет SMB/ping и админ-доступ по сети, напечатает имя ПК и IPv4.
3. **С ПК учителя**: `powershell -ExecutionPolicy Bypass -File deploy\DeployPc.ps1 -Targets "10.x.x.x"` —
   скопирует сборку, установит агента и сторожа, поднимет агента в сессии ученика.
4. Проверка: `deploy\VerifyTestBuild.ps1 -Targets "все ip"` (хэш `agent.dll`, порт 7801, служба) и
   «Обновить сведения» в клиенте.

## Клиент учителя

Запустить `dist\client\NetcClient.exe`. Ключ и порты задаются в **«Настройки»** (пишутся в `netc.json` рядом с exe) и должны совпадать с агентами.

- **«Обнаружить»** — поиск агентов в своей подсети (UDP broadcast).
- **Список по умолчанию** — при первом запуске (когда рядом нет `netc_pcs.txt`) таблица сразу
  заполняется известными ПК класса: адреса из `ips.txt` и имена `R114-01…R114-24`. Список
  сохраняется в `netc_pcs.txt`; после «Обновить сведения» имена заменяются реальными именами ПК.
- **«Добавить ПК»** — вручную адреса из других подсетей (список в `netc_pcs.txt`).
- **«Обновить сведения»** — подключение к агентам и запрос имени ПК, пользователя, ОС.
- **«Просмотр экранов»** — стена миниатюр; двойной клик по плитке открывает окно
  **удалённого управления** (мышь и клавиатура).
- **«Трансляция / блокировка»** — трансляция экрана учителя на все ПК из списка
  (полноэкранное окно у ученика) и блокировка/затемнение экранов учеников.
- **«Питание»** — выключить / перезагрузить / завершить сеанс на выбранных ПК (или на всех).
- **«Сообщение»** — отправить ученикам текстовое сообщение (при желании — с ожиданием ответа).
- **«Файлы»** — отправить файл учителя на выбранные ПК и забрать файл с ученических ПК.
- **«Ограничения»** — ограничение приложений (чёрный/белый список), интернета (полная блокировка прокси +
  закрытие браузеров), **фильтр сайтов** (чёрный/белый список доменов через локальный прокси-фильтр),
  а также защита автозагрузки ученика (подозрительные скрипты убираются в карантин).
- **«Журнал»** — запросить у агентов журнал событий (питание, файлы, блокировки, тесты и т.п.).
- **«Тест»** — составить тест (вопросы с вариантами и номером верного) и раздать ученикам; клиент собирает результаты.
- **«Персонализация»** — централизованно задать обои (с режимом: заполнить/по размеру/растянуть/по центру/замостить),
  экран блокировки, тему (тёмная/светлая) и акцентный цвет на выбранные ПК. У каждой настройки
  своя кнопка применения: «Применить обои», «Применить» (экран блокировки), «Применить тему»,
  «Применить акцент» — применяется только соответствующая настройка, остальные не затрагиваются.
  Кнопка **«Сбросить к стандартным (светлая тема)»** возвращает ПК к стандартному виду:
  светлая тема, акцент по умолчанию, стандартные обои Windows, сброс экрана блокировки.
  Обои/тема/акцент применяются в сессии ученика (HKCU). **Экран блокировки — машинная настройка**
  (`HKLM\...\PersonalizationCSP`): агент сам её задать не может (нет прав), поэтому запрос выполняет
  служба-сторож `netc_watchdog` от SYSTEM (см. ниже).
- **«Включить»** — дистанционное включение ПК по **Wake-on-LAN** (MAC берётся из «Обновить сведения»).
- **«Закрыть окна»** — закрыть все окна и приложения на выбранных ПК, включая окна Проводника
  (рабочий стол и панель задач не затрагиваются); при необходимости — принудительно завершить
  процессы, не закрывшиеся добровольно. Принудительное завершение выполняет служба-сторож от
  SYSTEM, поэтому закрываются и приложения, запущенные **от администратора** (агенту это
  недоступно). Системные службы и сам агент не трогаются.

Кнопки «Экраны», «Трансляция», «Питание», «Сообщение», «Файлы», «Ограничения», «Журнал»,
«Тест», «Персонализация», «Включить» и «Закрыть окна» работают с **выделенными** строками таблицы,
а если ничего не выделено — со всеми ПК списка.

**Выбор целевых ПК в окнах действий.** Каждое окно действия (питание, сообщение, файлы,
ограничения, журнал, тест, персонализация, трансляция) сверху содержит полосу выбора:
кнопку **«Выбрать компьютеры…»** (список всех ПК с флажками, кнопки «Все»/«Никто»),
быстрые кнопки **«Все»/«Никто»** и подпись вида «выбрано N из M». Действие применяется
к отмеченным ПК. Изначально отмечены ПК, выделенные в главной таблице (или все, если ничего
не выделено).

## Порты

| Порт | Протокол | Назначение |
|---|---|---|
| 7801 | TCP | управление (зашифровано AES-GCM) |
| 7802 | UDP | обнаружение агентов |
| 7803 | TCP | поток экрана (зарезервирован) |
| 7804 | TCP | локальный прокси-фильтр сайтов (только 127.0.0.1, слушает агент) |

## Безопасность

Общий ключ (pre-shared) + AES-GCM на весь канал. Клиент без верного ключа отклоняется.

## Текущий статус

**Этап 0 (готов):** каркас обоих проектов; протокол с шифрованием; рукопожатие и
сведения о ПК; UDP-обнаружение; GUI учителя (список, обнаружение, обновление);
трей-агент; скрипты публикации и установки.

**Этап 1 (готов):** локальный канал служба↔агент (именованный канал);
захват экрана (GDI→JPEG) в сессии ученика; стена миниатюр у учителя;
окно удалённого управления (мышь/клавиатура через `SendInput`, нормированные
координаты). Поток экрана и ввод идут по порту 7801.

**Этап 2 (готов):** трансляция экрана учителя на учеников (полноэкранное окно
у ученика); блокировка/затемнение экранов (полноэкранное topmost-окно, перехват клавиш).

**Этап 3 (готов):** питание (выключить/перезагрузить/завершить сеанс), сообщения/чат
(всплывающее сообщение у ученика с возможностью ответа) и передача файлов в обе стороны
(учитель → ученик и ученик → учитель). Всё поверх порта 7801.

**Этап 4 (готов):** ограничение приложений (чёрный/белый список процессов), ограничение
интернета (системный прокси текущего пользователя + закрытие браузеров), тесты
(вопросы с вариантами, автоматическая проверка, сбор результата) и журнал событий агента.

**Устойчивость (готово):** служба `netc_watchdog` (SYSTEM) перезапускает агента в сессии
ученика, если его закрыли; сам агент защищён от двойного запуска. Служба также выполняет
машинные настройки персонализации (экран блокировки) и умеет **перезапускать агента по команде**
(действие `restart-agent` через общую папку `C:\ProgramData\netc\personalize`) — это включает
новую сборку агента **без перезагрузки ПК**.

**Персонализация (готово):** раздел «Персонализация» в клиенте учителя и обработка в агенте —
обои (режим), экран блокировки, тема (тёмная/светлая), акцентный цвет. Обои/тема/акцент —
пользовательские (в сессии ученика, применяются сразу). **Экран блокировки** задаётся машинным
ключом `HKLM\...\PersonalizationCSP`, куда у агента (обычный пользователь) нет прав; работу
выполняет служба-сторож `netc_watchdog` от SYSTEM — агент передаёт запрос через общую папку
`C:\ProgramData\netc\personalize`, сторож применяет и отвечает. Сброс экрана блокировки — так же.

**Защита (готово):** агент чистит подозрительную автозагрузку ученика (скрипты → карантин,
записи Run/RunOnce с интерпретаторами → удаляются) и пишет в журнал; скрипты в **общей**
«Автозагрузке» (запись доступна только администратору) агент отправляет в карантин через
службу-сторож (SYSTEM). Служба-сторож отключает гибернацию и автосон, чтобы `shutdown /h`
из скриптов не «выключал» ПК.

**Wake-on-LAN (готово):** агент сообщает MAC в сведениях о ПК; кнопка **«Включить»** в клиенте
шлёт magic-пакет (broadcast) — для дистанционного включения выключенных ПК (при поддержке WOL в BIOS/NIC).
